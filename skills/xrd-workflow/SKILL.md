# XRD 总工作流(流程锚)

## 0. 开工仪式(每轮先做)
1. **读状态**:找 `<数据所在目录>/workflow_state.json`(或用户告知的样品目录)。有则读入——当前阶段、已完成产物、用户已给信息、拟合目标、待决问题全部以它为准,不靠对话记忆。
2. **无状态文件**:按本 skill 从阶段 1 开始,先建状态文件骨架。
3. **确认目标**:阶段 1 中与用户确认的"拟合目标"就是本次任务的 objective。宿主若有**目标跟踪能力**
   (例如 goal 工具)则建/对齐之;没有就只记在状态文件的 `goal_statement` 里,**不因此阻塞**。
4. 每完成一个阶段/关键判定:**用写文件能力整体重写状态文件**(保持 schema)再继续 —— 跨对话续跑依赖它。
5. **面向用户的文字:一律用当前对话语言**(用户 2026-09-27)。本 skill 与配套文档全是中文,但那**只是给你读的**;
   **凡是用户会看到的文字,都用用户说话的那种语言** ——
   **提问框**(`ask_user_question` 的题干/标题/选项标签/说明)、**报告与答复**(阶段⑤报告、达标声明、R 值口径、
   收尾说明)、以及**你转述的工具信息**(引擎给的是英文,直引可以;**要转述就用用户的语言**)。
   判定很简单:**用户用什么语言跟你说话,你就用什么语言对他说话。**
   ⚠ **宿主不会替你翻译**:`ask_user_question` 的 schema 只有 `id/question/header/options[].label/description/
   multi_select`,**没有任何 i18n 字段**,标签原样进界面 ⇒ 语言只能由你自己选。
   **也不要中英并排**:那种双语是**插件注入行**的格式(见下条),不是你自己写给用户的文字的格式。
6. **插件注入进对话的行是中英双语的**(形状:`[标签]` 独占一行 → `language-zh- …` → `language-en- …`)。
   那是插件的输出,**不要照抄进你的答复** —— 读它,然后**按用户的语言**向用户复述要点。
   `language-zh-` 与 `language-en-` 两块说的是**同一条内容的两种语言**,
   **不是两条独立指令**:不要因为看到两遍就做两遍,也不要把它当成"用户提了两个要求"。

## 1. 五阶段机(总骨架,**不变**)

```
①识别 → ②初筛 → ③分相/定相 → ④精修 → ⑤报告
  │        │         │         │
  └────────┴─────────┴─────────┴→ 任一阶段目标不可达 → 询问用户修改目标或停止
```
各阶段细则在细分 skill:
- **阶段 1-3**(识别/初筛/分相)→ 加载 `xrd-preflight`
- **阶段 4-5**(精修/报告)→ 加载 `xrd-refinement`
- **工具参数与已知坑**(12 个工具怎么用)→ 加载 `xrd-tools` 手册
- **红线与工具契约**(pcr/occ/引擎/fp2k)→ `fullprof-pcr`(B 腿)+ 本文件 §3

### 1.1 阶段④(精修)的内部结构：三段式

> ⚠ **关系说明(用户 2026-09-20 明示)**：三段式**只对应五阶段里的"阶段④精修"**，
> **不是替换五阶段机**。①识别/②初筛/③定相 与 ⑤报告 都不变；下面是把**④这一个格子展开**。

```
阶段④ 精修
 ├─ Ⅰ CIF 建立与验证        ── 结构模型这一层先把关
 │    库/文献取候选 → 没有就 build_orbit 重构 → validate 体检 → fp2k 驱动单次打分(ladder:false)
 │    出口：一组"可精修的候选 CIF" + 每份的基线 R
 │
 ├─ Ⅱ 初步精修优化          ── 用带界引擎压到 R 值洼地，允许反复迭代
 │    手动引擎 / fp2k 驱动 → 看 fit_status + 基线 R + R 走向 → 前进/回退/换相
 │    出口：R 值进入洼地（该模型+数据在本阶段已无改善余量）
 │
 └─ Ⅲ GSAS-II 精确精修与交付 ── ⛔ 硬门控：须经 Ⅰ/Ⅱ 收敛
       xrd_refine_gsas → xrd_gsas_ops(review 审查) → xrd_export_cif / xrd_finalize
```

**推进判据（用户定 2026-09-21）**：流程**以"R 值是否降低"为唯一的主要推进判据** —— 每一轮推进的依据是这一轮比上一轮 R 降了多少；没降就不在同一模型上继续压。

- **用哪个 R**：0.5.1 起有两个 R 值 —— **推进与目标判定一律用 `rwp_mean`（重复均值，决策值）**；
  `rwp`（随交付 pcr 走的单轮值）**不用于推进判断**，它属于那份文件、用于流转与对账。
- **参数健康度与残余峰是"判读/输出信息"，不是推进门限**（用户 2026-09-21 明确："**参与峰与数据
  健康度不要写这么死**"）。手动引擎**存在漂移**（负 Uiso、参数顶界等）**不等于不能推进** ——
  有界 LS 会漂，但**导入 GSAS-II 后物理约束生效可能把结果恢复回来**（实例：负 U 值）。
  **健康度只是非极限模式下的输出值**：写进报告、供 AI 判读，不单独决定进退。
- **测量有效性仍须先成立**（与上一条是两件事）：`fit_status.flags`（未收敛 / 撞 `max_nfev` /
  参数顶界）意味着**这个 R 数字本身不可用**，先按 §6.2 **数值性**处置重跑 —— 这是"数字能不能
  拿来比"，不是"物理上健不健康"。
- **残余峰/异常峰只参与归因**（解释 R 为什么停住、下一步该动模型还是动数据），**不单独驱动推进**。
- **目标里必须有 R 作为引导**：按 §1.3 写成"**目标是 R 值小于某个值**"（由输入推出、非插件写死的
  常数），并落到"**哪一步把 R 压到多少**"的任务流上。

- **⚠ 边界：过程宽松、交付严格**（用户 2026-09-21 明确："**但是要提到正常输出最终精修结构时
  （非极限模式）要严格遵守物理限制**"）。上面"健康度不是推进门限"**只适用于推进过程**：
  **正常模式（非极限模式）下最终输出 / 交付的精修结构，必须严格遵守物理限制** ——
  不得带着负 Uiso、占位越界、非物理热参等进入交付物。过程中出现的漂移，**要么在 GSAS-II 里靠
  物理约束恢复回来，要么必须在交付前修掉**；修不掉的只能按 §6.5 极限模式处理（**显式声明**、
  **不替换交付**）。判据落在 `xrd_gsas_ops` 的 `review` 与 `xrd_export_cif` 的 `anomalies`/`verdict` 上。

**分叉与短路**：若 Ⅰ 之后 **fp2k 的打分已经足够低**（参见 §3 的阈值），**可以直接跳进 Ⅲ**，
不必走 Ⅱ —— Ⅱ 的存在意义是"fp2k 驱动/手动引擎还能再压"的那种样品。

**回退与重复（沿用 `rounds[]`）**：三段式**不是单向流水线**。R 值变差 / 残差出现系统性起伏 /
`fit_status` 报"没跑完"或"参数顶界"，都可以退回上一段或换相重来；允许**只跑其中一段**做小工作流
（例：只做 Ⅰ 的 CIF 体检、或只做 Ⅲ 的 GSAS 收尾）。

**判读依据（机器给的 + AI 判的）**：

| 信号 | 来源 | 含义 |
|---|---|---|
| `baseline_rwp` | `xrd_refine_manual` / fp2k 驱动 | **起点**有多差。没有它，"Rwp=38.9" 与"Rwp=94.6" 的差别看不出来 |
| `fit_status.flags` | `xrd_refine_manual` | 未收敛 / 撞 `max_nfev` / 参数顶界 ⇒ **这个 R 值不是极小值**，不得当结果上报 |
| `ladder` | `xrd_refine_auto` | 多参数族**逐步**的 R 走向（判洼地的主依据，见下） |
| `review` | `xrd_gsas_ops` | GSAS 侧的 Uiso/占位/wR 合理性 |

**R 值洼地（数值洼地）的定义 —— 用户定（2026-09-20，操作性判据）**：

> 原话："**R值优先判据（其他不考虑），在最近的三次手动引擎尝试中R值没有降低，则认为是数值洼地。**"

- **只按 R 值判断，其他因素一律不考虑**。
- **判据**：取**最近三次手动引擎尝试的 Rwp —— 没有一次比之前更低，即判定达到数值洼地**。
  **⚠ 此处 Rwp 指 `rwp_mean`（重复均值，决策值）**，不是随交付 pcr 走的单次 `rwp` ——
  单次值有 ±1.5 量级噪声，拿它来数"有没有降"会把噪声读成"没降"，**凭空造出一个假洼地**。
- **取数来源**：`journal.jsonl`（append-only，逐轮记 `Rwp`）—— 取最后三条比一次即可，不凭记忆。
- **先排除"假平台"再谈洼地**：这三次里若有任何一次 `fit_status.flags` 非空（未收敛 / 撞
  `max_nfev` / 参数顶界），那**不是洼地，是没跑好** —— 先按 §6.2 的**数值性**处置重跑，再重新数三次。
  **走 fp2k 驱动时没有 `fit_status` 字段**，等价检查看 `ladder` 里的 `unstable` / `Rwp_spread` / `ok`。
  （注意这条与"**健康度不是推进门限**"不冲突：这里排的是**测不准的 R**，不是**物理上不好看的参数**
  —— 后者照 §1「推进判据」办理，漂移可以留到 GSAS-II 用物理约束恢复。）
- **洼地之后**：**停止在同一模型上继续压 R**，转入 Ⅲ（GSAS-II 精确精修与交付）。
- **驱动引擎自带的 `r_plateau` 只是辅助信号**（判断"这一次拟合是否干净"），
  **洼地的正式判据以上面"最近三次"为准**。

**机器判据是地板、AI 判读是天花板**（用户 2026-09-19）：上表是**必看**的下限；在它之上，
AI 仍可因材料语义（相变、缺陷、择优取向）做出表中没有的判断，但**不得无视表中任何一条告警**。

### 1.3 精修目标的标定约定（用户定 2026-09-20）

> 原话："**给出的精修目标要以任务流形式标定执行，但是目标不能硬标定为：'R小于某个值'，
> 而是标定为'目标是R值小于某个值（根据输入设计类似表述），如果按工作流中所有尝试均未达到理想结果则如实报告'。**"

**为什么这样写（用户 2026-09-21 说明）**：这条约定的**目的是避免"数据本身有问题、目标达不到，
却反复实验进入工作流死循环"**。所以关键是把**写法**与**语义**分开：

1. **写法上必须有具体数** —— 写成"**目标是 R 值小于 ≈8**"这类带数字的表述（该值由输入来源 /
   材料 / 前人结果推出，**不是插件写死的常数**）。原话里被否掉的**不是"带数字"**，而是
   **把那个数字当硬门限**；被肯定的正是"带数字、但只作参照"。**这是同一句话的两半，不矛盾。**
2. **语义上它是参照与引导，不是门限** —— **达不到不等于任务失败**，但它**也不是无限重试的许可**：
   走完工作流该走的尝试（含 §6 检查表路径）仍未到目标时，**如实报告"未达到 + 到了哪里 + 为什么"
   然后收尾**；**不得因为没达到就回到同一模型上反复试参** —— 那正是本条要防的死循环。
3. **照样输出** R 值与三件套，并说明拟合未达标（"即使精修存在问题，例如不拟合等，也输出 R 值，
   与三件套，并说明拟合不达标"）。
4. **目标以任务流形式标定并执行** —— 目标要落在 §1 的流程上（哪一段做什么、顺序是什么、
   在哪一步判定目标达成），**不是一句孤立的数字**。

**与 GSAS 门控的关系**：门控**不因"达不到目标"而软化** —— 手动侧**已无法继续改善**（上面的洼地判据）
即可交 Ⅲ，**不需要先达标**。

### 1.4 收尾清理约定（用户定 2026-09-20）

> 原话："**在确认精修完成后清理工作目录，仅保留日志，拟合记录文件，最终要求输出的结果
> （保留内容不确定时询问）。具体工作文件不保留。**"

**触发时机**：**确认精修完成之后**才清理。**分析/精修进行中一律不清理** ——
中间产物是判读与回档的依据（`.out`/`.prf`/`.gpx`/`.fp2k-work-*`/`.verify-*` 等），
提前删掉等于毁掉现场。

**保留（三类）**：
1. **日志**：`xrd_workflow/journal.jsonl` + `journal.md`（**权威记录，必留**）；
2. **拟合记录文件**：精修留下的记录性产物 —— **以 `journal.jsonl` 的 `artifacts` 字段点过名的为准**
   （`.out`/`.sum`/`.lst` 等）；**原话里的"拟合记录文件"指的是这一类，不是"随手看哪份留哪份"**。
3. **最终要求输出的结果**：用户要求的交付物（报告、图、CIF、交付包 `*_final/`、GSAS 工程等）。

**不保留**：**具体工作文件**（中间工作副本、临时计划/结果 JSON、scratch 副本、一次性的 `.prf`、
`backup_*`、精修过程目录等）。

**不确定时先问**：**保留内容不确定的，必须问用户**，不要自行判断后删除 ——
删除是不可逆的，问一句的成本远低于误删一个交付物。

**与"产物只追加不可变"的关系**：清理发生在**任务收尾**，不是过程中的回档 ——
回档靠 §1.2 的 `snapshot`，清理时**至少保留最终采用的那份快照/交付物**。




**约定书写规范（用户 2026-09-21）** —— 本文件与其余 skill 里凡是**用户原话**成条的约定，一律按此写：

- **原话逐字保留、不润色**；**解释写在引文之外**（引号里是证据，引号外是我们的落实）。
- **短句原话离开上下文会指代不明**（如"失败即换手段并不对""这个是要确定的"），必须在紧邻处补一句
  **"指的是：…"**，否则后来的会话会猜错对象。
- **原话与后来的决定冲突时**：**保留原话**（它是决策史），但在同一块内标明
  **"⚠ 已被 <日期> 的决定取代"**，并统一按 **"冲突以现状为准"** 执行。
- **自相矛盾的原话（如"不能标定为 R<某值"又"标定为目标是 R 值小于某个值"）必须当场合一**：
  写清**被否掉的是哪一半**（把数字当**硬门限**）、**被肯定的是哪一半**（带数字但只作**参照**），
  而不是把两半并排留给读者。
- **审这些条目的排序标准**：**"会不会导出一个具体的错误动作"** 优先，而不是文风。
- 改约定前**先把检查结果报给用户、等他点选再动手**（用户 2026-09-21 明确要求）。



## 1.2 统一日志与回档（用户设计 2026-09-19）

**位置**：工作目录 `<cwd>/xrd_workflow/`
- **`journal.jsonl`** —— **权威**，**追加写、机器可读**，每跑完一轮精修追加一行。
  **由引擎自动写入**（`xrd_refine_manual` 已内置；不要靠"记得手写"，那就不叫日志了）。
- **`journal.md`** —— 人读速览，**每次从 jsonl 整体重新生成**（不是另写一份），
  存在意义只有一个：**扫一眼就知道进度与卡在哪**。固定表头：
  `轮次 | 引擎 | 段/档 | 模型 | Rwp | 基线R | 判读 | 为什么 | 产物`。
  告警会直接并进"判读"列（例如"未到洼地；⚠撞 max_nfev=8000；2 个参数顶界"）。

**每条字段（定死，不再扩张）**：
```json
{"round":2, "engine":"xrd_refine_manual", "stage":"structure", "model":"物理",
 "trigger":"AI 判读 | 输入事件", "checklist_item":null,
 "plan_digest":"scale,zero,a,U,V,W,eta,bg0,bg1,bg2",
 "Rwp":38.91, "baseline_Rwp":94.56,
 "fit_status":{"success":false,"hit_max_nfev":true,"n_at_bound":2,"flags":["..."]},
 "verdict":"R 值洼地 | 未到洼地", "why":"由谁判、为什么这样判",
 "artifacts":{"result":"...","components":"..."}, "snapshot":"某步的 .gpx",
 "from":null}
```
- **`trigger`**：这一轮是**输入事件**（如工作人员手工精修失败）触发，还是 **AI 语义判读**触发 ——
  两者都要写清，这是"检查表何时被触发"的可追溯凭据（见 §6）。
- **`model`**：`物理 | 兜底 | 极限`。**极限模式的结果在日志里必须能一眼认出**（见 §6）。
- **`why`**：不是复述参数，而是**判读理由**（"残余峰 26.5° 未被解释"这类）。
- ⚠ **`Rwp` 字段 = `rwp_mean`（重复均值，决策值）** —— **不是**随交付 pcr 走的单次 `rwp`。
  判洼地、比轮次、写 `verdict` 一律用它（0.5.1 起两个 R 值的分工见 §1「推进判据」）；
  字段本身**不新增、不扩张**，只是把口径钉死。
- 供 `plan` 传入的可选键：`trigger` / `checklist_item` / `model` / `why` / `snapshot` / `from`；
  引擎其余字段（Rwp/baseline/fit_status/verdict/artifacts）自己填。

**回档**：**产物只追加、不可变**——这是回档成立的前提。回档 = **取某一轮的 `snapshot`（该步的
`.gpx` 或精修后 pcr）另存为新的工作副本再往下跑**，**不覆盖**任何既有产物。
"回到哪一轮"靠 `journal.jsonl` 的 `round` 指认；换分支时把新记录的 `from` 指向被回退的那一轮。

**日志末尾的"总结章节"（用户 2026-09-25，D4）**：每个样品**跑到收尾时**，在 `journal.md` **末尾追加固定小节**
（已有则整体重写），让该样品目录**自足可交接**、不依赖全局记忆（全局库只放工具层，见 §8 第 6 条）：

```
## 材料与目标
## 相与晶体族（结论 + 依据 + 被排除的族与理由）
## 缺陷总表（穷举 → 筛查 → 执行）
## 已达结果（R 与口径分开写；FullProf Rwp 与 GSAS wR 不可直接比）
## 未试 · 未决项          ← 不得留空；全都试过也要写"无"，把"没试"和"试过无效"分开
## 接手建议
```

小节名**固定**（便于机器校验）；内容与 `workflow_state.json`/`defect_table.json` 同源，**不要写出互相矛盾的两套数**。

- **判据顺序(用户定,2026-09-21 澄清)**：**R 值是否降低 = 唯一的主要推进判据**；

  尤其中间那条边界：**漂移/负 Uiso 不等于不能推进**（GSAS-II 的物理约束可能把它恢复回来）。
- **`no_improve_streak` 是"连续无改善"计数器（用户 2026-09-25，D11；沿用见 §6.7）**：每轮判读后更新 ——
  **R 未降或发散 ⇒ +1；出现改善 ⇒ 清零**（**严格连续**，中途改善即重计）；**达到 3 ⇒ 强制进入复杂情况检查表**。
  与 `limit_mode_attempts` **各记各的**（前者管"要不要查表"，后者管"要不要进极限模式"）。
- **`limit_mode_choice` 记的是「代号」，不是选项标签（用户 2026-09-27）**：§6.5 那道入口必答题的
  答案是**显示用**的（按当前对话语言渲染），而写进状态文件与 `journal.jsonl` 的必须是**稳定代号**
  —— `continue` / `retarget` / `informed_exception` / `handback`。理由：若记显示标签，中文会话写中文、
  英文会话写英文，**同一个决策在状态文件里变成两种字符串**，任何按值匹配的下游（"上次用户是不是选了
  知情例外交付"）都会断。这与"注入行双语、机器记录值不动"是**同一条原则**：**显示随语言变，机器读的值不变**。
- **⛔ 严格 JSON（用户 2026-09-25，D7）**：状态文件与一切机器读的文件必须是**严格 JSON** ——
  **AI 不手写数字**（`+2.04` 这类写法直接让文件非法），**写入后立刻自校验**（能 parse 才算写完），
  解析失败**不得静默**（报错并修，不要带着坏文件继续跑）。实测事故：`"dR": +2.04` 让 Python 与
  PowerShell 双双解析失败，后续判读全部落空。
- **一样品一子目录（用户 2026-09-26，D21）**：**会话内处理多样品时，每个样品建独立子目录**，
  该样品的**全部信息都落在自己的子目录下** —— 状态文件、`journal.jsonl`/`journal.md`、快照、
  审查的两个状态文件（`review_mechanical.json` / `review_judgment.md`，见 §8）、交付物。
  **跨样品不得共用一个目录**（计数器与判读都按样品隔离）。
- **任何对话恢复分析**:先读此文件,从 phase 继续;open_questions 未清前不得跳阶段。

### 6.5 极限模式（默认**不启用**）

> **目的**：回答"**这组数据 + 这条 CIF 路线，R 的极限在哪里**"，**不是**为了把 R 做好看。

#### 触发条件（三种，任一成立即触发）

1. **用户在对话中显式要求**（原话为主，不解释、不追问门槛）。
2. **强制触发（计数器驱动，不靠记忆）**：**完整执行复杂检查表（§6.2 失败四分类 → §6.3 逐级升级 → §6.4 D0–D5）
   三次之后，精修结果仍然达不到预期目标**（目标按 §1.3 以任务流形式标定，不是硬性的"R 小于某值"）
   ⇒ **必须进入极限模式检测**，不得继续在同一模型上无休止试参。
   - **"一次"的判定**：一次完整检查表遍历（含归类、按类处置、以及 §6.4 的缺陷过程）＝一次；
     单纯改动一个参数重跑**不算**一次。
   - **计数器落在状态文件里**：`workflow_state.json` 的 `limit_mode_attempts`（整数）与
     `journal.jsonl` 的对应轮次里各记一次，**每轮结束立即写**，不凭记忆判断"到没到三次"。
   - 三次未达预期 ⇒ 触发；此时**允许**直接进入，**不需要**再征求用户同意（这是既定流程），
     但**必须在报告里写明"因三次未达预期而进入极限模式"及这三轮的 R 值轨迹**。
3. **多次尝试后仍未达到拟合预设值**（与 2 同源，作为一般表述保留）。

#### ⛔ 进入极限模式前：必须发出显式选择题（用户 2026-09-22 定）

**触发点**：计数器到 3（"完整检查表三次仍未达预期目标"）。这一条**不是要征求进入许可**（进入本身按既定流程），
而是要求**在入口处向用户发一道必答题**，把选择权交回用户。

**必须用宿主选项框（如 `ask_user_question`）提问，并把判定证据放进问题里**（否则用户无从判断）：
当前最好的 R 值及口径、**统计极限 `Rexp` / `wRmin`**、两者差距；已完整走过检查表 **3** 轮（附三轮 R 值轨迹）。

#### 进入极限模式后的收尾输出规程（强制）

4. **就"当前最好的 GSAS-II 结果"计划收尾输出** —— 交付基线是 GSAS-II 口径（§1.1 红线：交付恒为物理模型）。
5. **若 GSAS-II 线路失败**（跑不起来、发散、无可用工程）⇒ **改走手动引擎线路**取当前最好结果收尾，
   并在报告里**显式说明线路已切换及其原因**，不得静默替换。
6. **显式报告最终结果**：必须给出 ①最终采用的模型与来源（GSAS-II / 手动引擎、哪个工程/文件）；
   ②R 值及其口径（FullProf Rwp 与 GSAS wR **不可直接比**，写清用的是哪个）；③是否达到目标，
   未达则写明**差多少**（与 `Rexp` 的差距，见下方判据）；④极限模式下试过什么、放开到哪一步、为什么停。
7. 极限模式的检测结果**照旧按红线处理**：**不替换交付**、非物理手段（负 Uiso 等）**绝不进交付**、
   日志 `model` 标 **`极限`**。

**放开顺序（先松物理约束，最后才动非物理自由度）**：

| 顺序 | 放开什么 | 说明 |
|---|---|---|
| 1 | **背景 / 峰形**（更高阶背景、独立 η、经验宽峰） | **逐阶放开，不要一次全开**：实测把 6 个背景系数一次性全开会让 Bck_2..5 爆到 10⁴–10⁵、χ² 反被毁；**只精修前 3 个系数**才是正确经验 |
| 2 | **LeBail 强度地板** | 每个反射强度独立自由，得到"结构模型还能不能再提升"的**地板**；地板≈实测值 ⇒ 参数族内已最优 |
| 3 | **占位 / 坐标约束** | 放开守恒与等值约束 |
| 4 | **热参下限** | 再往下就是**非物理自由度（负 Uiso）** |

**判据**：与**统计极限 `Rexp`** 对比 —— 说"到了极限"必须给出 Rwp 与 Rexp 的差距（例：物理版
Rwp≈13.5% 而 Rexp≈9.3%，要到 <10% 需额外消失约 60% 的残差，而物理手段预计只再降 1–2）。

**红线（不可越）**：
- 极限模式的结果**不替换交付**：交付恒为物理模型的 GSAS 口径；
- **极限模式的数值只允许出现在报告的「极限说明」一节**，**不得作为交付结论、摘要或图注里的数字** ——
  否则就是在"输出用户没要的值"（用户 2026-09-22 明确点出的风险）；
- **负 Uiso 这类"假晶体"手段只用于说明极限，绝不进交付**；若要走到那一步，必须**显式声明**；
- 日志里 `model` 字段必须标 **`极限`**，让后人一眼看出这条记录不是常规拟合。

### 6.6 高熵 / 占位表述材料的特例（用户 2026-09-22）

> 原话要点："**高熵/占位表述的材料拟合时，晶格会产生严重畸变，某些物理学约束可能失效，要谨慎否定 GSAS-II 的结果。**"

此类材料**晶格畸变严重**，因此**部分"物理约束"本身会失效**（键长窗口、热参下限、坐标合理性等判据不再可靠）。

- **「约束失效」≠「数值有效」**（这两件事必须分开）：判据不可靠时，**不得据此否定 GSAS-II 的结果** ——
  不因为它报了一条键长越界就把一次好拟合丢掉；但**真出现非物理数值**（负 Uiso、Uij 对角为负、占位越界）时，
  **仍按上面那条红线与 §6.5 的选择题处理**，**红线不因材料类别放宽**。
- **报告里要写清**：哪些检查对这类材料**只作提示**、不作为否定依据；以及为什么（畸变导致的约束失效）。
- 判据权重可以降，**数值有效性判定不可以降** —— 这是本节唯一的边界。

### 6.7 连续无改善 ⇒ 强制进表（用户 2026-09-25，D10/D11）

> 用户提议原话："例如 GSAS-II 连续出现三轮发散或 R 值没有达到目标设定值，且无法下降改善，**强制进入复杂问题检查表**"。

- **计数器**：`workflow_state.json` 的 **`no_improve_streak`**（整数）。每轮判读后更新：
  **R 未降 或 发散 ⇒ +1；出现改善 ⇒ 立刻清零**（严格连续）。**达到 3 ⇒ 必须进本检查表**，
  与 `limit_mode_attempts`（检查表执行次数 → 极限模式）**各记各的**。
- **触发后不得再用同一路数硬磨**：必须按 §6.2 归类 → §6.3 升级 → §6.4 D0–D5 走一遍；
  报告要写明**触发原因与三轮 R 轨迹**。
- **⚠ 关键口径（用户 2026-09-25，D10）**：**"发散 / 无改善" ≠ "不存在缺陷"** ——
  很可能是**缺陷存在但当前模型/引擎表达不出来**（SampleA 实测：手动引擎上加 K 劈裂反而更差，
  而参照物理解确实含真几何劈裂）。所以**不得因为"调了没改善"就放弃检查表或否定缺陷**；
  正确动作是**换一类解释重开假设空间**（§6.3 逐级升级 / 复杂缺陷直走 GSAS，见 §8 第 3 条）。

### 6.8 收尾覆盖检查与披露（用户 2026-09-25，D3；背景部分 D13）

**软门**：覆盖检查**不阻断收尾**，但**报告必须披露**：

- **单列"未试维度 + 理由"**；达标声明要标 **"未穷尽"**；
- **⛔ 禁止把"没试"写成"无法改善"** —— 这两件事必须在报告里分开；
- **宣告"已达极限 / 无法改善"之前，必须真的走过背景阶数升级**（手动引擎 `bg_scan` 逐阶 /
  GSAS `auto_background`），并在报告里写明**背景阶数与是否迭代过**；确实不适用要写**理由**，
  不能静默跳过。**不改变**既有规则（背景默认 6 阶、**必须最后拟合**、迭代非常规步骤）——
  只是把"最后一招有没有试"变成**可核查**的一件事。
- ⚠ **同时记住**：R 差距的主因通常是**缺陷模型**而不是背景；本条管的是"是否穷尽"，不是"背景是短板"。

### 6.9 "考虑其他问题" —— 表外情形倒回主表（用户 2026-09-25，D6）

- **附录 A（缺陷总表，`refs/defect-catalog.md`）只列已知缺陷类型**。遇到**表里没有**的缺陷或异常
  ⇒ **不扩写附录、不自创做法**，**倒回本检查表主表**按 §6.2 四分类与 §6.3 逐级升级处置；
- 确要试一个**表外的新假设** ⇒ 写进**每样品检查表**（`defect_table.json`，`source=unknown`、
  `id` 自拟 `X-01`…），**不动附录 A**；
- **每样品检查表 10 字段**：`id` / `defect` / `source`（可选，但引用别人的**具体数值**必须标来源）/
  `reported` / `verdict`(适用·不适用·待定) / `reason`（**不适用也要写**）/ `backend` /
  `geometry_ref`（几何敏感维度必填） / `exec`（`R_before → R_after`） / `status`（未执行**必须写理由**）；
- **附录 A 的两条可达性标记（D-06 有序-无序/超胞、D-09 配位多面体畸变）**：只在一个 CIF 上试不出来时
  **不得判"不存在"、也不得就此收尾** —— 必须回到 §6.3 Ⅲ 的 ①穷举晶体族 ②筛 2–3 个族取/造 CIF 对比，
  **逐条确认该 CIF 筛选确实执行过**，确认后才谈"不可分辨"。

**附录 A 尾注（三条特殊情况；一律走 GSAS-II）**：**层间阳离子混排**（归混占/反位，按占位守恒方案）/
**氧空位有序化**（归空位，必要时降对称或建超胞）/ **非化学计量整比偏离**（归空位，须与合成/ICP/EDS 输入对照）。
三者**不是独立条目、不单独精修**，只说明"按什么方式处理"。

## 7. CIF 从零构造的兜底（库与文献都查不到时）

> 触发：MP/COD 都取不到、文献只给了空间群与晶胞 —— 这时**不要凭坐标手敲 CIF**。

1. **`xrd_cif_edit` 的 `build_orbit {spacegroup, cell, sites}`**：每个位点只给**一个 Wyckoff 代表点**
   + 占位，由空间群自身轨道展开其余等价位置；返回每个位点落到的 **Wyckoff 字母与多重度**，
   **拿它与文献对照**（对不上就是抄错了）；
2. **`xrd_cif_edit` 的 `validate`**：在**原始文本层**核对位点轨道大小、展开胞原子数、**最小原子间距**。
   手写 CIF 最典型的坏法是把特殊位置的小数点写偏，解析器会**默默造出多余原子**
   （实测 6c 写成 x=0.04 → 生成 39 个原子、出现 0.115 Å 的重叠）；
3. **`cif_to_pcr`** 转换并看 `occupancy_check`；
4. **fp2k 打分**（`xrd_refine_auto {ladder:false}`）—— 结构化学上对不对**只能靠 R 值裁决**，
   因为**自洽的文件一样可以是错的结构**（层间距写错的文件完全自洽）。


## 8. 工作纪律（约定卡 —— 随插件走，不依赖任何本机记忆）

> **用户 2026-09-25 定**："**约定卡随插件走……但是要先筛选一下哪些约定是必须的，不加入过多约定，
> 影响其他同时安装插件+全局记忆的人。**" 筛选判据：**缺了它，插件在别人机器上就会做错事** ⇒ 才进卡；
> 已被通用记忆/环境纪律覆盖的**不进卡**（避免双份注入）；**本机路径、profile、记忆库用法一律不进卡**。
> 措辞用"**本插件在 XRD 精修时遵循……**"，不写"AI 行为总则"。

1. **R 值双口径，且跨来源不可直接比**：手动引擎的 `rwp`/`rwp_mean` 与 GSAS 的 `wR` 是**不同口径**；
   比较前先看 `wRmin` / `GOF` / `Rexp`。**交付恒为 GSAS-II 口径**（手动引擎数字只作旁证）。
2. **复杂缺陷必须走 GSAS-II**：**劈裂位点、反位物种、多占位耦合/守恒、额外物种**，以及任何
   **"缺陷是否存在"的判定** —— 一律在 GSAS-II 上做；**占位（OCC）等常规参数**手动引擎可用；
   **禁止用"手动引擎上加缺陷后 R 更差"来否定缺陷存在**。
3. **无改善即触发检查表**：**连续三轮（发散 或 R 未降）⇒ 强制进入 §6**（计数器 `no_improve_streak`）；
   **"发散/无改善" ≠ "不存在缺陷"**（§6.7）。
4. **收尾必须过覆盖检查**：报告单列"未试维度 + 理由"，达标声明标"未穷尽"；
   **"没试"不得写成"无法改善"**；宣告"无法改善"前必须走过背景阶数升级（§6.8）。
5. **状态与日志文件必须严格 JSON**，**AI 不手写数字**，写入即自校验，解析失败不得静默（§2、§8 第 6 条）。
6. **项目上下文留在工作目录、不依赖全局记忆**：一样品一子目录（D21）；
   样品级的数字、结论、未决项写进该目录的 `journal.md` 总结章节与状态文件（§1.2、§2）。
   **全局记忆只放工具层/方法论**（工具坑、引擎行为、流程口径），**样品科学数字不写入**。
7. **长流程要有显式 goal 给使用者看**（能力化：有目标跟踪能力就用，没有就落 `goal_statement`）──
   goal 稳定、todo 浮动，改目标只能由用户要求（§5）。

> **不进卡的内容与去处**（防误以为被取消）：数据配对规则、背景默认 6 阶且最后拟合、切峰门控 →
> 已在 `xrd-refinement` / `xrd-tools` 正文；证据分级 (a)/(b)/(c)、"不得声称全部已修复" →
> CHANGELOG 与 `verify-package.mjs` 断言；工具失败不得只抛错 → 插件工具描述；通用工具调用纪律、
> 沙箱与提权 → 环境级文档与本机全局 rules。

## 9. 复杂情况审查子代理（自动，2026-09-26 实施；使用者需知）

> 机制由插件自动运行，**不需要主 AGENT 或使用者发起**；这里只说明它会产生什么、以及要维护什么。

- **触发**：每 **3 个 GSAS 轮**（`xrd_refine_gsas` 每次调用 = 一轮）自动派生一个**临时复核单元**
  （从主对话派生、只读、用完即毁，超时 120 s）。它**不做精修**，只回一个代号（内部计数用）。
- **你会看到什么**：**等级 ≥ 2** 时，对话里会出现**一行** `[复杂情况审查 n/3] …`；
  等级 3 会带**冻结提示**并附 **§6 检查表全文**。等级 1 不打扰（更强的模型常能自己发现）。
  **判断栏落后 ≥2 轮**会出现一行 `[状态表]` 或 `[复杂情况审查 2/2]` 提醒。
- **你要维护**：样品子目录下的 **`review_judgment.md`（判断栏，AI 写）** ——
  **前半段**写人工输入窗口里用户说过的原话，**后半段**写：当前最佳物理解 / 未解决假设（逐条）/
  branch 列表 / 当前冻结状态；**整体重写、不追加**。**机械栏 `review_mechanical.json` 由插件维护，
  不要手改**（改了会被判成"人为接管"或造成状态不一致）。
- **冻结是软门**：不改任何工具的行为，只是提示"停止沿现有路线惯性优化、按 §6 重新评估"；
  **释放条件** = 判断栏里同时写明**已读检查表**与**新路线**。
- **人为接管 ⇒ 检测器自动关闭且不自动重启**：精修期间出现新的用户消息（或明说"我来接管"）即关闭；
  **只有明说"继续/交回"才恢复**，恢复时计数清零。**没有让模型自己关掉它的开关**。
