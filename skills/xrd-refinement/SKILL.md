# XRD 精修执行与报告(阶段 4-5)

> 由 xrd-workflow 总 skill 加载。前置:阶段 3 已定主相且大宽峰已扣/建模;读 workflow_state.json 确认目标。

## 阶段 4:精修执行

> **本文件实现的是阶段④的"三段式"**（定义见 `xrd-workflow` §1.1）：
> **Ⅰ CIF 建立与验证 → Ⅱ 初步精修优化（压到 R 值洼地）→ Ⅲ GSAS-II 精确精修与交付**。
> 三段式**只展开④这一格**，不替换五阶段机；①-③ 在 `xrd-preflight`，⑤ 在本文件后半。
> Ⅰ 与 Ⅲ 的工具用法见 §4.1 的入口与 §4.4 之后的 GSAS 章节。
>
> **遇到挫败先查表，不要直接换引擎**（用户定："**失败即换手段并不对，这个就是建立检查表的意义**"）：
> - **复杂情况检查表**（触发双层＝输入事件·人工拟合失败 + AI 语义判读；失败按 **数值/模型/结构/数据** 四类处置；
>   掺杂→第二相→高缺陷逐级升级）→ `xrd-workflow` **§6.1–6.3**
> - **缺陷的通用过程 D0–D5**（sampleC 只作示例；判据是"最小二乘把占位推向哪"）→ `xrd-workflow` **§6.4**
> - **极限模式**（仅显式要求或多次未达时启用；放开顺序＝背景/峰形 → LeBail 地板 → 占位坐标 → 热参下限；
>   **结果不替换交付**）→ `xrd-workflow` **§6.5**
> - **CIF 从零构造兜底**（库与文献都查不到时的 `build_orbit` + `validate` + R 值裁决）→ `xrd-workflow` **§7**
>
> **三条执行约定（用户 2026-09-20，必守）**：
> - **R 值洼地（数值洼地）的判据**：**R 值优先、其他不考虑** —— **最近三次手动引擎尝试 R 值没有降低**
>   即视为达到洼地；洼地后**停止在该模型上继续压 R**，转 Ⅲ。取数看 `journal.jsonl` 最后三条；
>   若这三次里有 `fit_status.flags` 非空，那**不是洼地而是没跑好**，先重跑再数。→ `xrd-workflow` **§1.1**
> - **目标标定**：以**任务流形式**标定并执行；**不得硬标定"R 小于某个值"**，要写成"目标是 R 值小于某个值"；
>   **按工作流所有尝试仍未达理想结果则如实报告**（照样输出 R 值与三件套，并说明未达标）。→ `xrd-workflow` **§1.3**
> - **收尾清理**：**确认精修完成后**才清理工作目录，**仅保留日志 + 拟合记录文件 + 最终要求输出的结果**；
>   **具体工作文件不保留**；**保留内容不确定时必须先问用户**。→ `xrd-workflow` **§1.4**

> **AutoFP 的 GUI/包装层已从插件里整体移除**(0.3.0),`xrd_refine_auto` 由**插件自带的无头驱动**
> 直接驱动 `fp2k.exe`(见 §4.2)。**换掉的只是那个读不了 CIF 转换器产出的 pcr 的旧包装,
> FullProf 仍是第一后端,"更快、更稳、可快速裁定候选 CIF"这些理由不变。**
>
> 用户定(2026-09-18 原话):**"autoFP优先于手动引擎,因为其更快,工作流更完善稳定,在有多个CIF候选时,可以快速确定候选CIF文件。"**

**按三段式落在哪一段，选工具：**

| **Ⅰ** | 取/造候选结构并体检 | `xrd_cif_edit`（`fetch_mp`/`fetch_cod`/`polymorphs`/`build_orbit`/`validate`）→ `cif_to_pcr`（含占位审计）→ `xrd_refine_auto {ladder:false}` **单次打分**排候选 |

### 4.2 xrd_refine_auto(插件自带无头 fp2k 驱动)
- **它是什么**:`engine/fp2k_driver.py` —— plan JSON 进 / result JSON 出,直接驱动 FullProf 的
  `fp2k.exe`,**不经 AutoFP、不起 GUI、不依赖 diffpy/pyfullprof 的 pcr 解析器**(那个解析器读不了
  官方 CIF 转换器产出的 pcr,会在 `pcrfilereader.py:749` 崩,并让工具误报 "did not report Rwp")。
  **只从 FullProf 安装里取 `fp2k.exe` 一个文件**(经 `$DSH_FP2K_ROOT` / `fp2k_root`（xrd.local.json） 解析)。
- **精修策略来自 AutoFP 源码的移植**(不是我们另发明):
  `scale → zero → simple background → cell a,b,c → W → complex background → V,U → Asym → Y,X
   → Atom x y z → Pref,Bov → Biso-Atom → GausS,1G → Occ-Atom → …`,
  规则同为"**一次只放开一组 → 跑 → Rwp 改善就留下,否则回滚**",目标函数 `MIN=Rwp`。
  `ladder:false` 只跑一次基线精修。
- **调用**:`xrd_refine_auto {pcr, cycles: 20, ladder: true}`(独立 job 目录 `.fp2k-work-*`)。
- **数据配对(实测红线,2026-09-21 更正)**:fp2k **按 pcr 的主名**(FullProf 的 job code)去找强度
  文件;`! Files => DAT-file: …` 那一行是**注释,不生效**。实测对照:正文声明 `Y2O3.dat` 且该文件
  **就在同目录**,只把 pcr 改名成 `probe.pcr` → fp2k 报
  `Error opening file CODEFIL.DAT… CODEFIL=probe`、**0 条 R 值行**;原名 `Y2O3.pcr` → 正常收敛 81.1。
  ⇒ **数据文件必须与 pcr 主名一致**(多 pattern 工程只有存在**非注释**的 pattern-file 名列表时才另说)。
  声称"按声明名读取"的旧结论来自一次**被同目录野文件污染**的实验,已作废(见 `fullprof-pcr`)。
  **后果**:声明名不存在时 fp2k 会**只打 banner 就静默停**(没有 R 值行,极易误判成"结构错")。
- **驱动顺带修掉转换器的两个输出缺陷**(否则 fp2k 直接打不开文件):
  ①相位名行 —— 转换器把 **CIF 文件名**写进去(`Y2O3.cif`),点号会让 fp2k 报
    `FindFMT: invalid character in a numeric field` 并中断 ⇒ 去掉扩展名;
  ②背景面板 —— 转换器写 Chebyshev(24 系数、8 行×6),其系数**对精修 code 不可见** ⇒
    改写为多项式(与"背景默认 6 阶"的约定一致),并把 Job 行的 Npr/Nba 一并校正
    (**注意:紧凑 Job 行不能按列名映射**,否则会误改 Nex 导致 fp2k 静默停)。
- **判据**:**以 `.out` 里的 R 值行为准**(驱动直接正则读取,不依赖 par.txt);
  返回值带 `ladder`(每组被接受的步骤及其 Rwp),这就是本轮的判读包。
  ⚠ **取哪个 R 值(0.5.1 起)**:决策看 **`rwp_mean`**(三次重复的均值 —— 选候选 CIF、判断是否够格
  直接进 GSAS-II 都用它);**`rwp` 是随交付 pcr 走的那个数**,属那一轮、那份文件,用于流转与后续对账。
  交付的 `refined_pcr` 是**起点状态**(精修它得到 `rwp`),写回那份(`*_end.pcr`)只作备份、不进流程。
  ⚠ **稳定性等价检查**:fp2k 驱动**没有**手动引擎的 `fit_status` 字段,判"这一次跑得干不干净"
  要看 `ladder` 里的 **`unstable`(离散 >0.5)/ `Rwp_spread` / `ok`**;这三个非空或异常时,
  这一轮的 R 同样**不拿来比**(与 §1.1"先排除假平台"同理)。
  崩/发散/Rwp 与预期差太远 → 报告原因后转手动,**不反复试错**。
- **旧的 AutoFP 红线已随之作废**(它们全部源于 diffpy 的解析/回写缺陷,现在不经过那一层):
  ~~禁用 complex background 组~~、~~回写 pcr 列粘连~~ —— 现在背景是**分级放开**的
  (先 1-2 项,再 W,再其余项),而不是一次全开。


### 4.3 xrd_refine_manual(py 引擎,可微调)
- 用途:需要**边界约束**(占位 0-1、峰形、η)、宽峰/小杂质、多相、或 AutoFP 失败时。
- 两步走:
  1. **init_engine:true** → 引擎模板复制到工作目录(engine 副本路径返回)。
     **AI 阅读该副本,必要时编辑模型区**(标记 `== EDITABLE ==`:峰形/宽度模型/
     背景/组分/约束),适配本材料。
  2. 调用 xrd_refine_manual {data, cif/atoms, out_dir, engine:<副本>} 运行;
     或直接用内置模板跑(参数化足够时)。
- stage_hint: calibrate(几何峰形) / structure(结构参数) / extras(宽峰) / twophase(第二相);
  AI 按工作流决定,或显式 vary/occ/extras/second JSON 精确控制。
- 每步产物:result.json(metrics+params+**structure**+**health**)、components.json(yobs/ycalc/bg/main/extra);
  AI 看 metrics、**health_flags** 与残差决定下一步;改善<0.3% 即收束,避免过拟合。
- **【视觉检测 V3】每轮精修后必须看图**（显式步骤;总表见 `xrd-workflow` §4,**不绑定具体视觉工具**）:
  看 obs/calc/残差图判断残差是**系统性起伏**(缺模型/缺相)还是随机噪声、有无整段未拟合、
  峰形是否被削平、背景是否吃掉峰 → 决定**前进 / 回退 / 换后端**。
  读图通道(**能力,不是工具**):①agent 自带多模态→直接读图(优先);②无原生视觉→**宿主视觉桥**
  (若已安装,例如 `modlens_read_image` / `office_read_image`);③都没有→**不得假装看过**,
  明说缺视觉能力并交用户人工看,或退回数值判据(残差表 / 分段 R 因子)。
  出图同样只要求**绘图能力**:首选本插件的 `xrd_export_cif` / `xrd_finalize` 成品图。

### 4.3.1 背景机制(用户 2026-09-18 重新声明,必须按此执行)
> 原话:"默认背景手动拟合与GSAS的AUTO background均采用6阶多项式,只有在其他条件均优化但仍然达不到目标时才启用背景拟合迭代,
> 直接从手动引擎拟合出不同多项式背景曲线直接导入GSAS,进行优化。"
> "显式迭代出曲线,需要考虑R值的边界效应,这个边界效应的R值使用手动引擎作为判断依据"

1. **默认固定 6 阶**:手动引擎与 GSAS AUTO background 都是 6 阶,**不迭代**。
2. **背景拟合永远是最后一个参数族**:其他参数全部优化完之后才碰背景多项式。
   背景先优化会吸收结构失配 → 结构"假收敛"。
3. **迭代是条件升级,不是常规步骤**:只有在**其他条件均优化、仍然达不到目标**时才启用
   (`bg_scan: true`)。启用后:步长 2、上限 20、逐级探测。
4. **迭代产物是逐阶背景曲线**:每阶导出 `bg_nNN.txt`(两列 2theta/background),
   再**直接导入 GSAS** 优化 —— `xrd_gsas_ops` 的 `import_background {source:".../bg_n10.txt"}`,
   GSAS 读作原生 `lin interpolate` 背景(20 个等间距插值点),可用 `vary` 决定是否继续精修。
5. **R 值边界效应以手动引擎 Rwp 为判据**(返回值 `boundary_r_basis` / `boundary_n_cheb`),
   **不看 GSAS wR** —— GSAS 是无界最小二乘,其 wR 可能在模型更差时反而更好看;
   越过边界的更高阶不参与选曲线。

### 4.4 fp2k 验证(xrd_verify_fp2k)

> **⚠ 这一步什么时候才有意义（用户 2026-09-22 追问后定）**：本工具是**跑单次 fp2k、不精修**
> —— 所以它的 **Rwp / BraggR 只有在 pcr 本身就是收敛过的 fp2k pcr 时才有意义**。
> **转换器（`cif_to_pcr`）造出来的 pcr 带着名义 profile 参数**，那种情况下 Rwp 只是"这套参数没被精修过"的写照，
> **不是对拟合结果的检验**（实测：拿 GSAS 导出的 CIF 转 pcr 再跑一次 → Rwp 61.1 / BraggR 94.7，
> 而同一结构的**密度与晶胞与 GSAS 完全一致** —— 有用的正是后两个）。
- **手动/引擎结果收敛后、需要发表口径背书**：pcr(occ 归一)跑 fp2k 验证 →
  密度(化学含量哨兵)、晶胞、Rwp、Bragg R;与引擎 a/zero/密度互证。
- **GSAS-II 交付之后再跑它**：**只取密度与晶胞两个哨兵**，**Rwp 一律注明"单次未精修"**，不得写进结论。
  这一步**不是交付的必含项** —— 不做它而直接交付，**不构成流程缺陷**。
- 引擎与 fp2k 的 a/zero/密度应一致量级;差异(背景/权重模型)报告时给区间。

### 4.5 GSAS-II 线 — ⛔ 硬门控（整条线都受门控）
> 用户规则（原话）："由于其复杂性和困难程度，仅作为最终优化使用，
> 不允许在没有使用 autofp 或手动计算得到前调用 GSAS"

- **前置门控（不可绕过，GSAS 全线适用）**：本样品必须**已由 `xrd_refine_auto`
  （插件自带无头 fp2k 驱动）或 `xrd_refine_manual` 得到收敛结果**，才允许调用 GSAS 线的任一工具
  （`xrd_refine_gsas` / `xrd_gsas_ops` / `xrd_export_cif` 的 gpx 源 / `xrd_finalize`）。
  GSAS 是最终优化，**不是第一引擎**，也不是前序引擎失败的替代重试通道。
- 触发：用户在前序引擎收敛后**主动要求**再优化/交叉验证，或前序结果需要
  "全参数可达可约束 + 官方导出"的收尾。
  **判据提醒**：FullProf(fp2k) 的 Rwp 与 GSAS wR 口径不同、不可直接比；说"GSAS 有改善"
  必须是同一数据同一模型下的显著改善，而不是跨口径的数字差。

**满足门控后，GSAS 线内部按三步走**：

1. **`xrd_refine_gsas` — 快速起步**：`{data, instprm, cif}` 新建工程，或 `{gpx:已有工程}` 续跑；
   `refine:["background","inst","cell","profile","atoms"]` 阶梯渐进（背景阶数 `n_back`；
   第二相用 `cif2` + `scale2_init`，scale/cell **`open2` 后置**开放，绝不与主相 cell 同一步）。
   - **Uiso 负值下限钳位（2026-09-19 加，默认关）**：`uiso_floor={"enabled":true,"min":0.005,"max_rounds":6}`。
     GSAS 自身**没有** Uiso 下限机制，热参可以被精修到 0 甚至负值（非物理，常见于过拟合/标度不当的模型）。
     开启后**每轮精修后**把低于 `min` 的 Uiso 抬到 `min` 并摘掉该原子的 U 标志（被钳的值不再算"测出来的"），
     继续精修直到某轮无新钳位。单位是 **U（Å²）**，B = 8π²U（0.005 U ≈ 0.39 B）。
     **默认关闭**是刻意的：有些模型确实会精修到很小/略负的 U（例如拆分或部分占位的位点），
     开关就是为这种情况留的口子。结束后会**实测**最终 Uiso 并在 `uiso_floor.final` /
     `n_below_floor_final` / `n_negative_final` 里回报，仍有越界会进 `warning`，**不静默接受**。
     实测：min=0.005 时 16 次钳位/3 轮收敛，结束后低于下限 0、负值 0。
   - **★ 逐相开关 `phases:[{...},{...}]`（0.8.10，下标＝`cif`/`cif2` 相序）**：每相可给
     `cell / scale / size / mustrain / hstrain / pref / atoms`（`mustrain` 可写 `"isotropic"|"uniaxial"|"generalized"`）。
     **这是"主相冻结、只放第二相"的配方**（教程式两相做法：主相关晶胞/尺寸/微应变，第二相只放相分数
     ＋单一各向同性微应变）。**不传 `phases` ⇒ 0.8.9 老行为**（每族一个全局步 + `cell2`/`open2`）。
   - **★ `entry` / `rollback`（0.8.10，默认随 `entry`）**：**续跑已有工程或带 `handoff` 时 `entry` 默认 `"hold"`**
     —— 先用一步验证来态，之后**一次只放一族**，只保留让 wR 变好的步，变差的**从快照回滚**；
     `"direct"` 是 0.8.9 的一次全放（无回滚，实测会把两相工程打崩：wR 30.42→77.19、晶胞被拉成 7.29/6.70/13.52）。
     **交付的是"最佳接受态"而不是最后一步**。`rollback_tol` 给 wR 容差（默认 0）。
   - **★ `handoff:"<手动引擎 result.json>"`（0.8.10，Ⅱ→Ⅲ 交接）**：把有界手动引擎配好的双相解播种进 GSAS
     （第二相相比例 / 主相晶胞 / 仪器 U,V,W,X,Y,Zero，带单位换算），随后照常走阶梯。
     **这是双相的正确入口**，细则与两条防线见 §4.5.3。
   - **★ 结果里的 `ladder[]` 必须看**：`step/label/wR_before/wR_after/accepted/rolled_back`，
     外加 `gsas_error`（**GSAS 自己报的失败**，例如 `Invalid cell metric tensor for phase #1`）
     与 `cell_change_pct`（该步里动了 >2% 的晶胞参数）。**失败步一律 reject＋回滚、绝不成为 best**；
     `warning` 只收"交付态被污染"的问题（失败步被保留／回滚失败／best 态恢复失败）。
     **回滚模式下若一步都没被接受，`summary` 会明写"交付工程即来态"** —— 别把 `ok:true` 读成"请求的族已精修"。
2. **`xrd_gsas_ops` — 全参数 / 可约束 / 工程级操作**（取代过去的一次性脚本）：
   - 参数：任意 hist section（`set_hist`）、cell、原子 flags/Uiso/占位/坐标、`scale`
   - 约束：`equiv_uiso`（分组等值 Uiso）、`uiso_clamp`（钳到 ≥min 并摘 U flag）、`split_site`（K 亚位）
   - **占位约束（2026-09-19 实测通过）**：
     * `equiv_afrac` —— **绑定**占位（`{"group":["Fe1","C4","N5"],"mult":[1,1,1]}`，`mult:[1,-1]` 即"差为 0"）。
       [Fe(CN)₆] 联动、K 亚位等值用这个（底层是官方 `add_EquivConstr`）。
     * `conserve_afrac` —— **守恒**：Σocc 钉住（`{"group":["K1a","K1b","K2a","K2b"]}` 保持当前总量；
       加 `"total":1.59` 钉到指定值；`"normalize":true` 先按比例归一）。
       底层是官方 **`add_EqnConstr`** —— 这才是"**等值约束不约束总量**、总量无界涨"的正解。
     * `check_conservation` —— 精修**之后**回读占位求和，`held=true/false` 由实测给出，**不要假定约束成立**。
     * **⚠ 硬前置**：GSAS 对"参数没在精修"的约束**静默丢弃**（`Ignoring this constraint; contains no
       refined parameters`）。两个 afrac 动作**默认自动开 F 标志**（`enable_occupancy_refinement:false` 可关），
       并在"组内成员已被等值互绑、总量其实冻死"时给出告警。
     * 实测：4 个 K 亚位自由精修时总量会漂（1.5142→1.5108），同一组加了守恒后**精确停在目标 1.5899**，
       且原有 K1a=K1b / K2a=K2b 等值关系被自动并入方程系统**同时保留**。
   - 工程级：`replace_phase`（换干净相，保留直方图/背景）、`add_phase`、`new_from`（派生工程+注入新数据）、
     `set_site_composition`（多元素共占位点）
   - **背景**：`import_background`（把手动引擎导出的 `bg_nNN.txt` 曲线导入为 GSAS 原生
     `lin interpolate` 背景）；`auto_background` **默认只做单次 6 阶**，
     `iterate:true` 才是升级迭代（`isolate` 默认隔离，避免连带精修 cell/profile）
   - **⛔ 背景必须最后**:`auto_background` 必须是**最后一个改参数的动作**,其后只允许 `save`/`snapshot`,
     否则工具**直接报错拒绝**;`import_background` 只有 `vary:false`(固定背景)时才允许其后继续精修
   - 返回**全参数表**（value/stderr/vary + flags）**+ `review` 合理性审查块**，可审计；
     参数细节与坑 → `xrd-tools` §5
3. **`xrd_export_cif` / `xrd_finalize` — 输出**（见阶段 5；gpx 源出图+CIF+科学判断，finalize 出交付包）

**判据与注意**：
- GSAS wR 相对 AutoFP/手动 Rwp **显著改善**才值得报"最终优化"；改善微弱则说明已到数据极限，如实说明。
- **必须审查 GSAS 输出**（用户要求:"GSAS-II输出的数据需要AI AGENT简单审查其合理性,例如没有特别错乱的U值等"）：
  每次 `xrd_gsas_ops` 都返回 `review` 块 —— `verdict` = pass/warn/fail，
  `flags` 列出负 Uiso / Uiso 过大或归零 / 占位越界 / wR≥50% 发散。
  **`verdict=fail` 时不得把结果当作完成结构报告**；先排障（改约束、钳位、或退回有界引擎）。
- **⚠ 热参数先看 ADP 模式（用户 2026-09-22）**：`review.adp` 会给出**各向同性 / 各向异性原子数**，
  每个原子行也带 `adp`。**GSAS-II 按原子上的模式标记决定精修哪个热参，不看 refine flags** ——
  标记为 `A` 的原子精修的是**六个 Uij**，它的 Uiso 列只是未动的初值，因此**所有 Uiso 类检查（含钳位）都够不着它**。
  所以：**要么用 `xrd_gsas_ops` 的 `set_adp_mode` 明确切到 `isotropic`（会把六个 Uij 清零）**，
  要么就按各向异性**看 U11/U22/U33 对角**（`review` 已按此检查，对角为负 = fail）。
  **不要**在 `adp=A` 的工程上宣称"Uiso 已钳到物理值"。
- **高熵 / 占位表述材料的特例**（用户 2026-09-22）：此类材料**晶格畸变严重 ⇒ 部分物理约束本身失效**，
  **要谨慎否定 GSAS-II 的结果**（不因为一条键长越界就把好拟合丢掉）。**但边界很清楚**：
  这只降低**判据权重**，**不改变数值有效性判定** —— 真出现负 Uiso / Uij 对角为负 / 占位越界，
  仍按上面的红线与 `xrd-workflow` §6.5 的选择题处理，**红线不因材料类别放宽**。
- **口径标注不是必含项**（用户 2026-09-18 明确"口径标准不需要声明"）；
  跨引擎数字不直接比较这一点自己心里有数即可，不必写进报告。
- **GSAS 的 LS 无界**：弱反射第二相若放开 scale 会发散（实测被推到 1e13）→ 改"**固定 scale2 单点交叉验证**"，
  或退回手动引擎（有界 LM）；**不要反复重试**。
  0.8.10 起这条有了机器兜底：失败步（`gsas_error`）与变差步都会被**回滚**，交付的是最佳接受态，
  所以"跑坏一步"不会再污染交付 —— 但**别把它当许可**：仍然要先按 §4.5.3 把两个最多的相配好。
- **⚠ 第二相太弱的双相样品不要硬做**（用户 2026-10-02 裁决，实测依据）：S3（CuCr2O4+CuO，7 K 帧）
  里 CuO 的积分强度只有主相的约 **1%**（sumInt 1230 vs 82811），它的相分数会被精修吞掉、
  峰形/晶胞参数本质不可测 —— 我方最好 **22.19%** vs 官方 **13.859%**。
  **判据**：先看第二相的强度占比与独立反射数，**弱到会被吞掉就该如实说"这个双相样品不适用"**，
  而不是把 R 值差距当成引擎缺陷。
- 缺 GSAS 格式（需 `.fxye` + `.instprm`）时先用 `xrd_data_io` 转换，不硬跑。

### 4.5.1 复杂缺陷一律在 GSAS-II 上做（用户 2026-09-25，D8 —— 被列为"最严重的问题"）

> 用户原话要点："**手动引擎实际上并不适用于高缺陷模型**，其缺陷部分拟合远远达不到 GSAS-II 的水平……
> **手动引擎保留缺陷的初衷是在兜底输出时有缺陷功能可用，而不是让 AI 使用手动引擎拟合缺陷。**"

- **必须在 GSAS-II 上评估**：**劈裂位点、反位物种、多占位耦合/守恒、额外物种（结晶水/碳酸根等）**，
  以及**任何"缺陷是否存在"的判定** ⇒ **直接走 GSAS-II**，不必先用手动引擎探一遍。
- **手动引擎仍可用于**：占位（OCC）、背景、峰形、晶胞、坐标等**常规参数**。
- **⛔ 禁止**用手动引擎的（复杂缺陷）结果**否定缺陷存在** —— 否定只能来自 GSAS 结果或统计判据。
  **实测证据**：同一 K 劈裂假设，手动引擎 **15.13 → 16.61**（V / cx_K1b / eta 撞界 box-limited），
  而 GSAS-II **14.41 → 13.71（全场最优）**；参照物理解确实含真几何劈裂（1.502 Å）+ Fe–N 反位。
  **只看手动引擎就会得出"缺陷不存在"的错误结论。**
- 与既有边界一致：占位守恒属于 GSAS（手动引擎不实现）—— 本条把该边界**从"守恒"扩展到"复杂缺陷"**。

### 4.5.2 几何敏感维度：**双方案并列**（用户 2026-09-25，D1）

对**劈裂位点、反位、以及任何"是否该拆成两行"的维度**，必须在缺陷总表里**给出两行数字**：

- **(i) 自由方案**：坐标 + 占位同时放开。若两行合并 ⇒ 结论只能写"**本数据分辨不了**"，
  **不得写成"该缺陷不存在"**；
- **(ii) 约束方案**：几何**取自出处**（文献值 / 化学键长区间 / 对称性推导 / 用户给定），**只精修占位**。
  若出处给的是区间或多个候选，**至少试 2 个值**（例：劈裂距离试 1.3 Å 与 1.5 Å）；
- **⛔ 禁止只用一个自定几何值就排除该维度**。实测后果：SampleA 曾只试 **1.2 Å**（R 15.75）就判"排除"，
  而参照物的真几何是 **1.502 Å**；
- **反位**（如 Fe–N）不涉及几何，其对应方案是**占位守恒约束下精修**（`conserve_afrac`/`equiv_afrac`），
  **不得因为自由精修把反位推向 0 就判"无反位"**；
- **排除该维度的唯一合法条件** = 两方案都跑过 + 几何有出处 + 数字齐全（`R_before → R_after`）；
  否则 `verdict` 只能写**待定**。（缺陷类型清单见 `xrd-workflow` §6 附录 A。）

### 4.5.3 双相与多相：**先用手动引擎把两个最多的相配好，再 handoff 进 GSAS-II**（用户 2026-10-02 定的设计顺序）
> 用户原话（2026-10-02）："**如果先使用手动引擎调配好双相再进入 gsas-II 呢，实际上设计顺序是这样的。**"
> 我当时的错误是把"GSAS 阶梯不会 bootstrap 双相"当成引擎缺陷；**真正的缺口是 Ⅱ→Ⅲ 的交接契约** ——
> 相分数这一类双相解此前**没有任何传递入口**，GSAS 只能从 1:1 重新开始，把差值吸收进背景与峰形。

**双相（2 相）**：
1. **Ⅱ 上解**：`xrd_refine_manual` 带 `second:[{cif:...}]` 把**两相一起配到位**（有界 LM，相分数/峰形/晶胞都在界内）。
   **必须真的收敛**：看 `metrics.Rwp` 与 `fit_status.flags`；**某相被拟合成 ≈0 就是没配好**，回上一步重配。
2. **交接**：调 `xrd_refine_gsas` 并传 `handoff:"<上一步 result.json>"`（外加 `gpx`，或 `data`+`instprm`+`cif`+`cif2`）。
   引擎播种相比例、主相晶胞与仪器参数，并在 `handoff.transferred / not_transferred / warnings` 里**逐条说明
   传了什么、没传什么、为什么**。**两条防线会挡下坏种子**：某相被拟合 ≈0 → 告警；仪器值与工程差 >10 倍 → **拒绝覆盖**。
3. **Ⅲ 收尾**：`entry="hold"`（带 handoff 时默认）逐步放开＋回滚；`phases[]` 按需逐相（主相冻结、第二相只放相分数与单一各向同性微应变）；
   需要约束/背景再上 `xrd_gsas_ops`；最后 `xrd_export_cif` / `xrd_finalize`。
4. **判读**：只看 `ladder` 与最终 wR。**失败步（`gsas_error`）说明该族在这份数据上不可测** —— 如实写进报告，不要反复重试。

**≥3 相**：走独立工具 **`xrd_refine_multiphase`**（**硬门控 ≥3 相**，1–2 相它会直接拒绝）。
它的第二入口是 **AI 可编辑代码钩子**：`init_engine:true` 取模板 → 改标了 `# == EDITABLE ==` 的编排段 → 传 `engine:"<那份副本>"` 执行。
**同样必须先用手动引擎把最多量的两个相配好再 `handoff`**（不带 handoff 的新建工程会被拒绝）。

### 4.6 目标不可达处理
- 地板(LeBail)或结构平坦性分析证明参数族内已最优/数据极限 → 停止精修尝试,
  向用户说明证据,提议:改目标(如"名义占位陈述"而非精修确定)/ 补数据 / 停止。
- **禁止**:无意义的反复尝试(换 seed 不改善、调边界来回试)。

#### 4.6.1 宣布"无法改善"前必须先**披露覆盖度**（用户 2026-09-25，D3 + D13）

**"发散 / 无改善" ≠ "该缺陷不存在"**（D10）。在写"无法改善 / 已到数据极限 / 该缺陷被排除"之前，报告里**必须有一行覆盖度声明**，逐项写清"试过什么、没试过什么"：

- **背景阶数**：当前用的阶数，以及**是否已做背景阶数迭代（`bg_scan` / `auto_background` 提升阶数）**。
  **顺序是硬规则**：背景**永远最后拟合**（默认 6 阶）；**只有在其他参数全部优化完、仍打不到目标时**才允许升阶，
  且升阶属于**升级动作**（D13），升到哪一阶、每阶 `R` 的变化都要写出来。**未做升阶就必须写"未做背景阶数升级"**，
  不得把"6 阶下的残差"说成"数据极限"。
- **参数族覆盖**：这次**实际放开过哪些参数族**（晶胞 / 峰形 / 占位 / 坐标 / 背景 / 仪器 …），哪些**一次都没放开**。
- **几何敏感维度**：是否按 §4.5.2 给了**双方案并列**（自由 + 有出处的约束），各方案的 `R_before → R_after`。
- **模式边界**：是否因本阶段的后端能力而**没做**某件事（如复杂缺陷 / 占位守恒 → 见 §4.5.1，**必须转 GSAS-II**）。
- ⚠ **"未试" 与 "无法改善" 是两件事**：只要覆盖度里还有"未试"的项，结论就只能写**"在已试范围内未改善"**，
  并**同时列出未试项与建议的下一步**。软门只在"已试范围"内成立（收尾软门的定义见 `xrd-workflow` §6.7–6.8）。

#### 4.6.2 撞上 `max_nfev` / 参数顶界时**禁止只降 nfev 重试**（用户 2026-09-25，D18⑤）

- `fit_status.flags` 报 `未收敛` / `撞 max_nfev` / `参数顶界` ⇒ **该次 R 值不是极小值，不得当结果上报**。
- **⛔ 禁止**把 `max_nfev` **调小**再跑一遍当作"已穷尽"的证据；也禁止靠反复换 seed 制造"试过了"。
- **正确处置**（按顺序）：
  1. **诊断**为什么撞：参数间强相关 / 初值太远 / 约束缺失 / 模型自由度超出数据信息量；
  2. **改模型或改约束**（合并相关参数、加守恒约束、固定不可分辨参数、换等价但更正交的参数化）；
  3. 需要更多评估次数时**允许提高** `max_nfev`（而不是降低），并把该次标记为**升级动作**；
  4. 仍撞 ⇒ 按 §4.6.1 写**覆盖度声明**，结论只能是"在已试范围内未改善"。
- **每次尝试都要留档**：`xrd_workflow/journal.jsonl` + 缺陷总表（`R_before → R_after`），
  撞界的那一次要**显式标注"撞界、值无效"**，不得混入"已排除"的判据。

## 阶段 5:报告与输出

### 5.0 统一输出端口 `xrd_export_cif`（四个源，三条路线共用）
- `gpx` 源（GSAS 工程）→ 图 + **GSAS 工程副本** + CIF（structured / official）+ **科学判断**
  （空间群、最近邻键长统计、`<min_distance` 接触、occ 越界、可选 `bond_expect` 窗口 → `verdict`）
- **`result` 源（手动引擎 `result.json`）★** → **精修后 CIF**（含空间群检测）+ 拟合图 + 科学判断。
  这是**手动引擎接入 GSAS 三件套的通道**：手动收敛 → `result` 源出 CIF → 交给 GSAS 继续优化/交付。
- `components` 源（手动引擎 `components.json`）→ 图 + **残差诊断**（rms、最大残差点位置）
- `data` 源（原始两列谱，**包含无法做精修的样品**：硬碳 / 无定形主导 / 杂质谱）→ 图 + `no_fit_model` 提示
- **输出永不阻塞**：图与 CIF 永远先写出来；`sanity:false` 可整体跳过校验；不科学值列在 `anomalies` 中，
  由**人手工精修**解决（用 `xrd_gsas_ops`），而不是被工具拦下
- ⚠ **但"工具不拦" ≠ "可以交付"**（用户 2026-09-21 明确："**但是要提到正常输出最终精修结构时
  （非极限模式）要严格遵守物理限制**"）。上一条是**工具层**的红线（输出接口不得阻塞、不得替用户
  做科学判断）；**流程层**另有一条：**正常模式（非极限模式）下最终输出 / 交付的精修结构必须严格
  遵守物理限制** —— 不得带**负 Uiso、占位越界、非物理热参**进入交付物。分工是：
  **工具照常写出 + 标 `anomalies`** → **AI 必须据此在交付前修掉**（改约束 / 钳位 / 换模型），
  修不掉的按 §6.5 极限模式**显式声明**且**不替换交付**；过程中允许的漂移见 `xrd-workflow`
  §1「推进判据」（过程宽松、交付严格）。
- 交付包：`xrd_finalize` → `<sample>_final/`（干净 gpx + lst + 每相 CIF + 防遮挡图 + report.md）

### 5.1 三件套 + 可选
1. **峰拟合结果表格**：相/峰参数、峰位归属、Rwp/Rexp/χ²、区域残差摘要。
2. **拟合结果图**:obs/calc/残差 + 分量(背景/主相/宽峰/第二相),含统计框与化学式。
   **出图走绘图能力(不是指定工具)**:首选本插件 `xrd_finalize` / `xrd_export_cif` 的成品图(遮挡规则见下);
   否则用宿主任意绘图能力(例如 python + matplotlib:写 PNG 前先删旧文件防覆写失败,`MPLCONFIGDIR` 指可写目录)。
   **【视觉检测 V4】交付前必须读图**（显式步骤;总表见 `xrd-workflow` §4,**不绑定具体视觉工具**）:
   看图例/统计框是否遮挡、hkl 标注是否压峰、坐标轴是否可读 → 出图卫生。
   通道:①agent 自带多模态→直接读图(优先);②无原生视觉→宿主视觉桥(若已安装);③都没有→**不得假装看过**,
   明说缺视觉能力并把图交用户人工审。
3. **峰归属图**:实测谱 + 各相理论峰位 ticks 对照,审阅归属。
4. **CIF**:用户要求才输出(含占位/缺陷语义;双 block 写法按需)。
5. **交付包 xrd_finalize(GSAS 最终结果推荐路径)**:当用户要"可直接交付/归档的成果集"
   (干净工程 + CIF + 效果图 + 报告)时,调 `xrd_finalize {gpx:<已收敛工程>, sample, title, formula}`,
   输出一个目录 `<out_dir>/<sample>_final/`:
   - `<sample>_final.gpx` 干净工作工程(自动清理已删相残留的反射表);
   - `<sample>_final.lst` 精修日志(chi**2 / GOF 由日志解析,工程内不存这些量);
   - `<sample>_<相>.cif` 每相一份,**GSAS 官方 `export_CIF` 生成(禁手写 CIF)**;
   - `<sample>_fit.png` 效果图:obs 点/calc 总/背景/相分量 + 残差面板 + **每相一行峰位刻度**(峰归属),
     最强峰带 hkl 标注;图例与统计框按数据占据度自动选角、主图顶部留白 → 不遮挡峰;
   - `<sample>_report.md` 指标/晶胞(含 esd)/原子/强反射表。
   本工具**只打包**:不重跑精修、不改任何参数;Uiso/退化修复属未来功能,不在其中。
   `xrd_finalize` 需要一个**已收敛的 .gpx**;因此**手动引擎结果要先经 `result` 源出 CIF、
   再进 GSAS 收敛成 gpx**,才能走交付包 —— 这就是"手动引擎也能用 GSAS 三件套"的路径(用户 2026-09-18 要求)。

**诚实性声明**(报告必含):
- 参数平坦(不可辨识)按名义固定并明说,不伪造 esd(引擎 stderr=0 时不给 esd);
- 宽峰/主体组分纠缠时不得读作相分数;孤立宽峰才可半定量;
- 未建模项(择优取向/微应变/吸收)列明;
- **缺陷排查覆盖度声明（用户 2026-09-25，D3/D6）**：凡走过复杂情况检查表（`xrd-workflow` §6），报告里**必须**带
  ①**每样品缺陷总表**（`defect_table.json` 的 10 字段，**排除项也要写 `reason`**，见 §6.9 与附录 A `refs/defect-catalog.md`）；
  ②**覆盖度**（§4.6.1）：背景阶数 / 是否做过背景升阶 / 实际放开过哪些参数族 / 几何敏感维度的双方案 / 因后端能力而**未做**的事；
  ③**结论口径**：只要覆盖度里还有"**未试**"，就只能写**"在已试范围内未改善"**，**不得**写成"无法改善 / 缺陷不存在 / 已到数据极限"；
  ④**撞界的那一次**（未收敛 / 撞 `max_nfev` / 参数顶界）**显式标注"撞界、值无效"**，不得计入"已排除"的判据（§4.6.2）；
- **失败必须分类，不得一律记成"故障"（用户 2026-09-25，D18③）**：报告与日志里把每次失败归到三类之一 ——
  **①设计内拒绝**（工具按门控有意拒绝：切峰未带 `confirm`/`reason`、`edit` 的旧串未命中、越界参数被拒 …）、
  **②真故障**（引擎崩溃、驱动 exit ≠ 0、R 值缺失且产物异常）、
  **③环境限制**（缺依赖、权限/沙箱拒绝、网络失败、视觉桥不可用、超时预算耗尽 …）。
  **只有 ② 才算模型/代码缺陷**；把 ①③ 记成故障会污染"缺陷总表"的判据，也会让用户误以为插件坏了。
